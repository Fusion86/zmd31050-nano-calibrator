# zmd31050-nano-calibrator

Arduino Nano / PlatformIO tool for Sensortechnics SSI pressure sensors using
the ZMD31050 signal conditioner. Reads digital pressure over I²C, compares it
with analog OUT, backs up EEPROM, and tests the DAC output.

All code in this project was generated by AI.

## Wiring

Use a classic 5 V ATmega328P Nano. Connect sensor SDA to A4, SCL to A5,
analog OUT to A0, and share ground. Use suitable external I²C pull-ups
(4.7 kΩ is a typical starting point). Keep A0 within 0–Nano VCC and leave
AREF unconnected with the default firmware. I²C runs at 100 kHz, address `0x78`.
Set the supply-voltage constants in `src/main.cpp` to measured values.

For my calibration I did not use external pull-ups and did also not change the voltage constants. Because I am lazy, and it seemed to work fine anyway.

## Build and run

```sh
pio run
pio run --target upload
pio device monitor --baud 115200
```

Send a key through the serial terminal:

| Key | Action |
| --- | --- |
| `h` | Show help |
| `b` | Read EEPROM twice, verify signature, and decode settings |
| `d` | Read digital pressure and compare with A0 voltage |
| `1`, `2`, `3` | Hold DAC output at 25%, 50%, or 75% of sensor supply |
| `r` | Resume measurement using saved EEPROM calibration |
| `c` | Apply the sensor-specific temporary RAM calibration |
| `s` | Permanently save the verified RAM trial to EEPROM |

## Calibration

The included correction is specific to one **SSIB001AU9AH5 (0–1 bar absolute)**
sensor and its recorded EEPROM baseline; it is not a universal calibration.

Keep an external original EEPROM backup before using calibration functions.
Power-cycle the sensor, wait at least 100 ms, and send `c` as its first command.
Verify reference pressures with `d` before saving. `s` writes EEPROM and checks
all 32 words and the signature; keep power connected until verification finishes.
After saving, `r` loads the new calibration and does not undo the save.

See [calibration notes](docs/ram-calibration.md). The 11-bit DAC cannot output
exactly 0.500 V at 5 V; the model predicts DAC code 204 (0.498 V) at 0 bar, so
vacuum reads just below a strict 0.5 V cutoff. This was accepted as is.

### Supply voltage during calibration

During calibration, the Nano ADC reference was initially assumed to be 5.0 V;
it was later measured at approximately **4.85 V**. The sensor was powered from
the Nano's same 5 V line. With `analogReference(DEFAULT)`, the ADC reference
uses the Nano's AVCC supply; the sensor supply and ADC reference therefore
tracked the same rail approximately, with AREF left unconnected externally.

Because the sensor's analog output is ratiometric, this shared supply largely
cancels out when comparing analog ADC counts with digital sensor counts.
The calibration was based on those digital counts, so the assumed voltage did
not materially affect its normalized endpoint correction. However, voltages
displayed using 5.0 V were about 3.1% too high: a nominal 0.500 V target at
5.0 V corresponds to approximately 0.485 V at 4.85 V, before quantization.

After calibration, the sensor was disconnected from the Nano and installed in
the original equipment, whose supply was verified at **5.0 V**. Its ratiometric
analog output should therefore return to the nominal 0.500 V / 4.500 V endpoint
scaling at that supply, subject to quantization and calibration accuracy.
The Nano's shared ADC reference explains the calibration measurements; in
production, the relevant factor is the sensor's ratiometric output at 5.0 V.

The firmware voltage constants still default to 5.0 V; set both to measured values for
accurate voltage reporting.

## Analysis and reference documents

Optional analysis scripts in `docs` generate plots and an Excel model using
`matplotlib`, `numpy`, and `XlsxWriter`. The plotting script expects local
`pumped.txt` and `vented.txt` captures. Logs and generated artifacts are excluded
from Git.

Protocol reference:
[ZMD31050 Functional Description, Rev. 0.82](docs/ZMD31050_Functional_Description_Rev_0.82.pdf),
sections 2.2, 4.5, and 5.4.

Datasheets and related vendor PDFs in `docs` are included for reference; copyright
and any usage restrictions remain with their respective owners.
